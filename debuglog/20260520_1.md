# 2026-05-20 Bruno 登录 401 排障记录

## 问题
- 在 Bruno 中调用管理员写入接口时返回 401。

## 结论
- WordPress REST API 鉴权应使用 Application Password，而不是网站登录密码。
- 当前站点为 HTTP，导致 Application Password 功能默认不可用。

## 现象与原因
1. Application Passwords 用于 REST API/XML-RPC 的非交互认证，不能用于后台网页登录。
2. WordPress 默认要求 HTTPS 才启用 Application Passwords。
3. 当站点未启用 HTTPS 时，Profile 页面会提示该功能不可用。

## 环境类型说明
- `WP_ENVIRONMENT_TYPE` 可选值：`local`、`development`、`staging`、`production`。
- `staging` 的含义是“预发布环境标识”，不是“关闭安全限制”。
- 按当前源码默认逻辑，Application Password 可用条件是：`is_ssl()` 或环境类型为 `local`。
- 因此：HTTP + `staging` 仍不可用；HTTP + `local` 可用于本地开发调试。

## 修复方案
1. 本地开发环境：在 `wp-config.php` 中添加以下配置（放在 `/* That's all, stop editing! Happy publishing. */` 之前）：

```php
define( 'WP_ENVIRONMENT_TYPE', 'local' );
```

2. 进入用户资料页重新生成 Application Password。
3. Bruno 使用 `Basic Auth`：
- username: WordPress 用户名
- password: Application Password（不是登录密码）

## 验证方式
1. 用 Bruno 请求一个需要管理员权限的端点（如 `POST /creation-categories`）。
2. 预期从 401 变为 200/201（或业务校验错误 4xx，但不应再是权限失败）。

## 安全备注
- 应用密码属于敏感凭据，不应保存在仓库日志中。
- 原记录中的应用密码已删除，建议存入本地环境变量或 Bruno Secret。
